## Overview

Agent Trace is a code attribution tracking system that records which AI agents/models generated which code, complying with emerging AI transparency requirements and implementing the [agent-trace.dev](https://agent-trace.dev/) specification.

### What It Tracks

- ✅ Which AI agent/model generated each piece of code
- ✅ Exact file location and line numbers
- ✅ User prompts that led to the code
- ✅ SHA-256 code hashes for integrity verification
- ✅ Metadata (tokens, duration, programming language, etc.)
- ✅ Operation type (generation, edit, deletion)

### Use Cases

1. **AI Code Attribution** - Track which AI generated what code for licensing compliance
2. **Debugging** - Trace bugs back to the agent and prompt that created the code
3. **Productivity Analysis** - Understand which agents are most productive
4. **Compliance Auditing** - Generate reports showing all AI contributions
5. **Code Review** - Review AI-generated code by agent, file, or time period

## Configuration

### Environment Variables

| Variable | Required | Default | Description |
|----------|----------|---------|-------------|
| `AGENT_TRACE_ENABLED` | No | `false` | Enable/disable Agent Trace system |
| `DATABASE_URL` | Yes | - | PostgreSQL connection string |

### Database Schema

**Table**: `code_attributions`

| Column | Type | Description |
|--------|------|-------------|
| `id` | UUID | Primary key |
| `session_id` | VARCHAR(255) | Conversation/session ID |
| `agent_id` | VARCHAR(255) | Foreign key to agents table (nullable) |
| `agent_name` | VARCHAR(255) | Agent display name |
| `model` | VARCHAR(255) | LLM model used |
| `file_path` | VARCHAR(1000) | File location |
| `start_line` | INTEGER | Starting line number |
| `end_line` | INTEGER | Ending line number |
| `change_type` | VARCHAR(50) | generation/edit/deletion |
| `code_hash` | VARCHAR(32) | SHA-256 hash (first 32 chars) |
| `prompt` | TEXT | User prompt (nullable) |
| `generated_code` | TEXT | The actual code |
| `metadata` | JSONB | Additional data |
| `created_at` | TIMESTAMP | Creation timestamp |

**Indexes**:
- `ix_code_attributions_session_id`
- `ix_code_attributions_agent_id`
- `ix_code_attributions_file_path`
- `ix_code_attributions_code_hash`
- `ix_code_attributions_created_at`
- Primary key on `id`

## API Endpoints

All endpoints are available at `/api/v1/trace/*`

### GET /trace/health
Health check for Agent Trace subsystem.

**Response**:
```json
{
  "status": "healthy",
  "subsystem": "agent_trace",
  "database": "connected",
  "totalAttributions": 250,
  "uniqueAgents": 5,
  "uniqueFiles": 45,
  "timestamp": "2026-01-31T12:00:00Z"
}
```

### GET /trace/stats
Get attribution statistics.

**Response**:
```json
{
  "totalLines": 15000,
  "totalAttributions": 250,
  "uniqueAgents": 5,
  "uniqueFiles": 45,
  "byOperation": {
    "generation": 100,
    "edit": 120,
    "deletion": 30
  },
  "topAgents": [
    {
      "agentName": "Claude Sonnet 4.5",
      "totalLines": 8000,
      "attributionCount": 120
    }
  ],
  "topFiles": [
    {
      "filePath": "/app/api/trace_routes.py",
      "attributionCount": 15,
      "totalLines": 500
    }
  ]
}
```

### GET /trace/recent?days=7
Get recent attributions within the last N days.

**Parameters**:
- `days` (integer): Number of days to look back (1-90)
- `limit` (integer): Maximum results (1-1000)
- `offset` (integer): Pagination offset

### GET /trace/files/{file_path}
Get all attributions for a specific file.

**Parameters**:
- `file_path` (path): File path (URL-encoded)
- `limit` (integer): Maximum results
- `offset` (integer): Pagination offset

### GET /trace/agents/{agent_id}
Get all code generated by a specific agent.

**Parameters**:
- `agent_id` (string): Agent identifier
- `limit` (integer): Maximum results
- `offset` (integer): Pagination offset

### GET /trace/sessions/{session_id}
Get all code generated in a specific session/conversation.

**Parameters**:
- `session_id` (string): Session identifier
- `limit` (integer): Maximum results
- `offset` (integer): Pagination offset

### POST /trace/report
Generate a compliance report with optional filters.

**Request Body**:
```json
{
  "agentId": "claude-sonnet",
  "filePath": "/app/api/",
  "changeType": "generation",
  "startDate": "2026-01-01",
  "endDate": "2026-01-31",
  "format": "csv"
}
```

**Supported formats**: `json`, `csv`

## Troubleshooting

### Issue: Table doesn't exist

**Solution**:
```bash
python scripts/migrate_trace_table.py
```

### Issue: Foreign key constraint violation

**Problem**: Trying to use `agent_id` that doesn't exist in `agents` table

**Solution**: Use `agent_id=None` for agents not in the database

### Issue: Health check fails

**Check**:
1. Database connection
2. Table exists
3. Permissions on `code_attributions` table

### Issue: No attributions appearing

**Check**:
1. `AGENT_TRACE_ENABLED=true` in .env
2. LLM client integration is active
3. Agents are actually generating code

## Security Considerations

### Data Protection

1. **PII in Prompts**: Prompts are stored in the database. Ensure sensitive data is not included in prompts.
2. **Code Hashing**: SHA-256 hashes provide integrity verification but do not protect code confidentiality.
3. **API Access**: Use API keys in production (`X-API-Key` header).

### Access Control

- API endpoints require authentication in production
- Set `AUTH_BYPASS=false` in production
- Use `BRIGADE_ADMIN_KEY` for administrative access

### Compliance

- GDPR: Prompts may contain personal data - implement retention policies
- SOC2: Full audit trail of code generation
- License Compliance: Track AI-generated code for attribution

## Maintenance

### Database Cleanup

Remove old attributions (>90 days):
```sql
DELETE FROM code_attributions
WHERE created_at < NOW() - INTERVAL '90 days';
```

### Backup

Backup the `code_attributions` table regularly:
```bash
pg_dump -h localhost -p 5434 -U leads_user -d unicorn_brigade \
  -t code_attributions -f code_attributions_backup.sql
```

### Performance Tuning

If queries become slow:
1. Add additional indexes on commonly queried fields
2. Partition table by `created_at` for large datasets
3. Archive old data to separate table
